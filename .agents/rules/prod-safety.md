# Production Safety Rules — TimeTracker v2

Этот проект — переезд живой SaaS-системы (Express/vanilla JS) на React + Vite + TS + Tailwind + Neon. У старой системы ЕСТЬ платящие клиенты прямо сейчас. Эти правила действуют ВСЕГДА, без исключений, до момента явного разрешения от пользователя на финальное переключение.

## Жёсткие запреты

1. **Никогда не изменяй, не удаляй и не перезаписывай что-либо в исходной продакшн-системе** (старый репозиторий/старая ветка/старая база), если пользователь явно не попросил об этом отдельным сообщением. Работай только в новом проекте/новой ветке.
2. **Никогда не подключайся к продакшн-базе данных Neon/Postgres напрямую** для разработки или тестов. Используй только staging/dev-базу, пока пользователь явно не подтвердит переход к финальной миграции (Фаза 5 ТЗ).
3. **Никогда не переключай прод-домен или primary alias на Vercel** без явного запроса пользователя в текущем сообщении.
4. **Не удаляй файлы или таблицы БД без явного подтверждения** — предлагай план и жди подтверждения перед деструктивными операциями (DROP, TRUNCATE, force-push, `rm -rf`).

## Обязательный порядок работы

5. Двигайся строго по фазам из раздела 9 технического задания (`TZ_TimeTracker_v2.md` в корне репозитория, если он есть — открой и следуй ему). Не переходи к следующей фазе, пока пользователь явно не подтвердил текущую.
6. После завершения каждой фазы — выдай ссылку на preview-деплой и краткий список изменений. Не пиши "всё готово" без работающей preview-ссылки, которую можно открыть и проверить руками.
7. Если в процессе работы кажется полезным "заодно улучшить" что-то вне текущего скоупа фазы — сначала спроси пользователя, не делай этого самостоятельно.
8. Секреты (JWT_SECRET, DATABASE_URL, VAPID-ключи, CRON_SECRET и т.д.) — только через переменные окружения Vercel/`.env` (в `.gitignore`). Никогда не хардкодь секреты в код, даже "временно для теста".

## Бизнес-критичная логика

9. Формулы расчёта рабочего времени (ночные часы, сверхурочные, автовычет обеда, биллинг) должны совпадать с исходной системой 1:1. Перед изменением любого файла, связанного с расчётом часов/биллинга, свериться со skill `timetracker-business-rules`.
10. При любых сомнениях в трактовке требования — переспроси пользователя, а не додумывай по своему усмотрению. Это система с реальными деньгами и реальными людьми.
